# PokeCatch Tools

基于 **Vue 3 + TypeScript + Naive UI + Vite / vite-plugin-monkey** 的游戏助手。统一管理经验、敌情、对策模拟和捕捉队列，可拖动、收起，适配窄屏，样式与游戏隔离。统计与模拟只读；自动捕捉在点击开始后操作原生地图和队伍。定期云保存默认每 15 分钟尝试，可在设置中关闭。

## 安装与升级

安装 Tampermonkey，再[安装统一助手](https://raw.githubusercontent.com/awoooochubby/pokecatch-tools/main/pokecatch-tools.user.js)。支持游戏 Netlify 和 Pages 域名，配置自动更新。

- 两个旧安装地址继续提供兼容更新，保留原 namespace。更新后均运行统一助手，单例机制避免重复面板。只需保留一个入口。
- **先更新两个旧脚本并刷新游戏。** 也可禁用旧脚本，只安装统一助手。未更新的敌情脚本没有卸载接口，已经运行时不能安全停止；混用旧版请禁用旧脚本并刷新。
- 首次升级复制旧版经验、整轮历史、最近单场、敌情本段与上一段到 `pc-tools-v1`，旧键原样保留。更早路段仅迁移能确认的当前阶段，不推测合并。
- 数据位于当前游戏域名的 localStorage，两域名不自动共享。设置中可导出记录与备份，不含游戏存档。

## 功能与口径

| 页面 | 功能 |
| --- | --- |
| 概览 | 累计经验、墙钟效率、当前弱点、最近倒下来源 |
| 经验 | 队伍进度、下一级估算、最近 50 场、与上一次手动统计的效率对比 |
| 敌情 | 跟随战斗或固定物种、属性倍率、本段和上一段伤害排行 |
| 回顾 | 本段最近战斗、倒下来源、本轮消息与飘字、历史整轮日志 |
| 对策 | Box 战损矩阵、逐级门槛、实际剩余路线、队伍排序与自动切换比较 |
| 追踪 | 目标绑定队伍、完整道中模拟、一键加入可抓缺失图鉴、游走跟随、天气插队、团战挂机、闪光蛋与自动收蛋 |
| 团战 | 原引擎预测完整团战胜率与双方出招数，单独搜索期望出招较少的阵容 |
| 刷图浮窗 | 模拟整章战斗后直接比较 XP/分钟，支持指定精灵；保留实测记录与排行 |
| 设置 | 定期云保存与服务端回执确认、模块启停、历史保留 1–100 轮、导出备份、统一版本 |

只累计存档中能确认的经验。初次接入不把已有 XP 当作收入；跨级仅计可确认部分并显示下界。等待、暂停、关闭页面均计入墙钟时长，死亡、回城和换轮不重置累计。手动开始新统计才清零，并保留上次效率作为比较基线。队伍、等级和采样完整度不同会影响比较；非战斗经验也可能计入。

原经验页的下一级时间按界面经验条与累计速度估算，至少采样 10 秒且有增长才显示。刷图浮窗单独使用经过当前游戏构建校验的升级经验公式补全跨级增长，口径见下文。

伤害读取实际飘字，包含溢出，不等于 HP 实际扣减。状态伤害不推测原始来源，不确定的直接伤害计入未归属。详见 [ENEMY-PANEL.md](ENEMY-PANEL.md)。后台、离线、动画跳过和存档延迟可能漏采，无法完整审计战斗。助手不直接写游戏存档、不替换游戏函数和时间源、不上传记录；自动追踪通过原生按钮切图，游戏自行战斗、捕获和保存。

## 开发

Node.js 22.12+（当前验证为 24）。使用锁文件安装：

```sh
npm ci
npm test
npm run test:engine
npm run build
npm run check:release
npm run test:browser
```

浏览器测试使用 Playwright。云环境已有 `/usr/bin/chromium`；其他环境先执行 `npx playwright install --with-deps chromium`，或设置 `CHROMIUM_PATH`。测试全部请求指向模拟游戏文档，不需账号，截图在忽略的 `test-results/`。

`npm run dev` 提供 vite-plugin-monkey 的 Tampermonkey 开发入口，在自己的浏览器中按终端提示安装；云端本地验收使用浏览器测试。

- `src/core/`：统一游戏适配、事件、存储迁移、模块生命周期。
- `src/modules/`：经验和敌情业务，不生成 HTML。
- `src/components/`：Vue / Naive UI 页面；`App.vue` 管理主题、拖拽和导航。
- `src/data/`：基础精灵与特殊形态。
- `tests/`：迁移、计算、生命周期与浏览器验收。

新增模块遵循 `FeatureModule` 的 start / stop，在 `runtime.ts` 注册。DOM 读取统一放进 `GameAdapter`；模块不得再开全页监听、独立采样计时器或写入游戏存档。界面通过 Vue 转义文本，Naive UI 样式注入 Shadow Root。

## 版本与发布

版本唯一来源是 `package.json`。改版后用 `npm install --package-lock-only` 同步锁文件，再运行构建。提交源码、锁文件和根目录三个 `.user.js` / `.meta.js` 配对产物，`dist/` 不提交。兼容入口只改变元数据身份，运行代码相同，禁止手改产物。

CI 执行单元测试、类型检查、构建、产物一致性和浏览器验证。当前通过模拟验收，**尚未完成 Tampermonkey 扩展安装和登录后真实战斗验收**。本地构建不等于已推送或发布。

## 对策分析（v2.1）

打开游戏页助手的“对策”，点击“读取本章敌情与 Box”。默认先给可读推荐，批量矩阵、排序和误差参数保留在高级设置。数据只在本机进入独立 Worker，不上传；章节变化自动更新，已有结果遇到敌人/队伍变化会提示重新读取。

- **Box 战损矩阵**：选候选和当前敌人 / 剩余路段目标。道中按区域最高等级，当前敌人保留实际 HP 和倍率；指定编号:等级的目标按普通野生战处理。单挑重新建队列，各样本独立。
- **升级门槛**：对选定精灵逐整数级测至该精灵适用上限（不超过当前上限），不假设变强一定单调。按胜率下界和战损上界是否满足可设置的门槛，标记第一个采样达标等级；不是数学保证。
- **剩余路线**：运行当前章节保存的实际剩余节点，按游戏遭遇逻辑选怪，继承血量和状态，中心正常治疗；等级保持不变，跳过经验、进化、捕获和货币奖励。未确认选择和特殊区域不伪造继续。
- **全局排序**：对所选最多六只队伍，同时比较自动切换开 / 关。四只以内枚举所有顺序，五六只比较基线与全部两两换位，不声称找到全局数学最优。每方案使用同组初始随机种子。

游戏开启自动切换后按进攻相克、防守抗性评分，已上场加 0.001，同分按出战队伍原顺序；不会比较真实伤害或先后手。关闭时按实际出战队伍顺序。仓库显示顺序不参与。存档的 road（实际队伍）与 team（计划队伍）可能不同；排序方案假设从当前位置生效，实际手动调整可能要等下一次出发。

先手速度、麻痹修正、同速随机、非暴击命中伤害区间、招式重排/继承、多段伤害和终结一击按当前线上原引擎处理，不用平均伤害除 HP 推算几下。命中次数报告包含终结一击，并明确只统计获胜样本。总期望战损包含失败样本。

**完整战斗不是解析精确期望。** 使用蒙特卡洛估计：胜率附 Wilson 95% 区间，期望缺血附有界经验 Bernstein 95% 区间，累计承伤和行动数附近似区间。有限样本全胜不等于必胜；区间是单组置信范围，不是多方案筛选的整体最优保证。

默认每组 256 次，可设 128–8192。每次最多 15 万条样本，超出需减少候选、目标或样本数；后台 Worker 可取消，十分钟超时。支持导出种子、条件、原引擎版本、快照时间与完整结果。

游戏构建从官方 CDN 按需读取，只有通过 SHA-256 审核的版本可执行，线上版本变化会拒绝沿用旧规则。没有把第三方游戏代码打包发布；测试需要 `npm run test:engine` 下载并校验忽略的 `.cache/engine.js`。详见 [计算口径与引擎适配](docs/counter-simulation.md)。

尚未读取你的真实浏览器 Box，也尚未完成登录后的游戏内验收；浏览器回归使用完整原引擎和模拟存档。

## v2.1.1 审查修复

## v2.2.0 刷图经验浮窗

点击助手顶部「刷图」可打开独立可拖动浮窗，关闭浮窗仍继续统计；设置中可停止整个统计模块。窄屏默认折叠到屏幕下方。每个冒险章节累计多轮记录，支持整队或指定精灵、最近 60 秒与累计速度、地图排行、单图重新测量及 JSON 导出。

采用出战 `road` 队伍的实际入账经验，跨级补回每一级消耗，达到上限丢弃的溢出经验不计入。含战斗、重复捕获及道具等实际经验，无法仅从存档拆分所有来源。有效时间包括走图与治疗，排除暂停、后台、关闭页面和不完整区间；首次读取、换图、换队、地区经验倍率变化重新建立基线。没有经过核验的新游戏版本只累计同级差值，跨级整段排除并提示，不猜测补录。

排行是历史实测，队伍人数、等级、经验加成和采样长度会影响结果，建议指定一只练级对象并在相同条件下每图测几轮。少于一分钟的记录会标注。具体规则与两章比较见 [地图经验分析](docs/map-experience.md)。

v2.2.0 引擎同步到官方 `cf8c0470ea` 构建。

## v2.3.0 直接模拟选图

「刷图」浮窗默认进入模拟选图：读取当前出战队伍，勾选当前地区已解锁的地图，直接比较整章实得经验、预计耗时、XP/分钟、完成率与倒下次数。每次点击比较都会刷新队伍快照，无需先切图实战挂机。原来的实测排行在「实测记录」保留。

模拟使用原引擎处理先后手、实际攻击次数、状态、中心治疗、中途升级、触顶溢出、伙伴加成/糖果和捕获。按实际入账统计快照队伍；失败尝试的经验和时间也纳入总经验/总时间。每个随机样本从相同快照开始，预测当前状态出发的一轮，下一轮等级变化后应重算。

**预测秒数采用游戏在线切到其他页面时的标准行动节奏，不承诺前台动画的精确耗时。** 当前基准为 `max(ACTION_MS, STEP_MS) / Adventure.speed()`，速度按游戏的 `SPEED_PACE` 换算。前台动画、手动停顿、图鉴和进化确认等会造成实测差异。区间只描述随机模拟误差，不含计时模型误差。漫游首领与其他系统的被动收益暂不计入；存在手动选择的地图会说明原因，不伪造结果参与排行。

默认每图 256 次，可选 128–2048 次，合计最多 8192 轮、最多 16 图。后台 Worker 可取消，支持 JSON 导出；队伍/经验/加成变化会提示快照过期。三个安装入口统一为 v2.3.0，未自动操作游戏切图或修改存档。详见 [模拟经验效率](docs/experience-forecast.md)。

## v2.4.0 联盟修复与可解释对策

修复阿柳等联盟章节因漏载原游戏 `LEAGUE_TEAMS` 队伍表而触发的空怪池错误；所有引擎入口共用一份数据依赖清单。对策页现在明确显示当前章节，分开“这场战斗”“本章后续”“指定精灵”，补齐固定训练家目标，野怪按原引擎的进化形态展示；随机训练家的队伍交战前不伪装成已确定。

主要流程变为“检查当前队伍能否撑到中心”以及“找一只更稳、省血的对策”。结果先展示精灵、等级、先后手、预计损血和推荐理由；数值参数折叠。可按中文精灵名指定目标，计算完成后自动定位结果。

路线解释来自实际模拟中的扣血与战败记录：显示最常见倒下位置、下一处中心、还隔几场战斗，并指出同一段路最耗血的敌人。可把该次真实模拟的敌人快照带入单挑寻找替补；保留原战斗规模与开战 HP。不会把单挑更强直接宣称为换队后整章必过，也不会给已经走完的样本编造失败原因。

三个安装入口统一为 v2.4.0；升级后刷新游戏并重新读取敌情/队伍再计算。

## v2.5.0 指定目标的实用配队

- 在“对策”里选本章目标节点，区分到达前、打完后；从章首满血出发，中心只在实际经过时回血。
- 优先保留原队，必要时比较换位、练级和最多两名替补。配置成本为训练分钟 + 换入人数 × 20 + 换位成本 1。
- 用原引擎连续刷图，估计全队一起达到建议等级的时间；计入伙伴奖励、升级、加成到期与失败重打，无法估时不会按零成本排序。
- 每个候选以 128 次初测筛选，至多四个方案用不同种子复核 512 次。展示换入/换出、等级、训练图、原因和通过率，支持报告导出。

这是有限搜索的可行解，不承诺全局最优。详见[目标配队口径](docs/team-planning.md)。三个安装入口统一为 v2.5.0。

## v2.5.1 下拉菜单滚轮修复

补齐 Shadow DOM 内虚拟列表的滚动基础样式，统一修复目标节点、敌人、物种、Box 候选和刷图地图等下拉菜单的鼠标滚轮。菜单到顶／到底时不会带着外层面板或游戏页面滚动，保留虚拟列表、搜索和多选。浏览器回归使用真实鼠标滚轮验证上下滚动和边界。三个安装入口统一为 v2.5.1。

## v2.6.0 副本目标与节点经验

- 联盟作为完整副本，包含四天王、冠军及全部道中；过内部章节只更新进度，不重置配队目标和已有报告。重新计算保留原副本目标。
- 配队从副本入口连续计算，道中战损、异常状态、原生中心和过场治疗都计入；模拟选图也将整个联盟合为一个选项。
- “刷图 → 本图节点”按顺序展示每处期望 XP、累计 XP 和到达率，可切换整队／单只、完整重打／按当前状态继续。过去节点与未知节点分别标识。
- 使用原引擎实际经验变化计算，计入途中升级、伙伴累计奖励、重复捕获和触顶，支持导出，不改游戏存档。

三个入口统一为 v2.6.0，详见[副本和节点经验口径](docs/dungeon-experience.md)。

## v2.7.0 神兽自动追踪与团体战预测

- “追踪 → 读取目标与天气”，选多个目标并调整优先顺序，点击“开始挂机捕捉”。游走神兽换位置自动跟随，捕获失败继续尝试，实际抓到后自动换下一个目标，全部完成后停止自动切图。
- 两种模式：不允许插队／允许插队。允许时优先抓当前天气出现、尚未拥有的稀有怪，抓到或天气结束后继续主目标；默认关注全部天气稀有怪，也可自选名单。
- 支持原生天气遭遇池和天气限定的定点形态，保留原生地区、时段、前置捕获及一次性条件。可进入的普通神兽区域也可加入主目标；解谜、周轮换形态、世界首领另行处理。
- 保持现有冒险队伍；独立神兽队伍不同、手动改队、地图入口失效时等待或暂停，并显示原因。保护进行中的战斗和捕获动画，追踪记录展示捕获与切图原因。
- 游走遭遇需要游戏标签页可见，可放在独立窗口。关闭、隐藏、休眠期间无法自动追踪；恢复可见后继续，刷新后保留目标但需重新开始。未处理的赠礼／解谜选择需要手动完成。
- 新增“团战”页，读取已配置的异色团体战，用原引擎做 512 次完整重打，显示击败首领的成功率和 95% 抽样区间；包含道中、中心、队友真实能力及首领特殊机制。模拟不修改游戏存档。

三个入口统一为 v2.7.0，使用方法和实现边界见[自动追踪说明](docs/legendary-tracker.md)和[团体战预测说明](docs/raid-prediction.md)。

## v2.10.0 团战搜索覆盖与闪光蛋／自动收蛋

- **全部可用好友与 NPC**：通过原生两名队友选择框取并集，只打开并取消，不改选择。包括好友＋好友、好友＋NPC、NPC＋NPC；保留原生 NPC 加成及好友实际 id／等级／闪光，不替好友虚构 NPC 加成或阶级。好友列表仅含当前原生提供的已共享参战队伍。保留好友优先／NPC 生成顺序；无法确认两名好友先后的组合分别模拟两种顺序，采用较保守结果。
- **公开搜索范围**：己方可选原生评分前 8／16 只或整个 Box；比较池内每个合法双宠组合的两种顺序。当前配置额外保留并独立复核。默认分轮搜索先覆盖所有队友对，用前三支队友对改进己方，再用前两支己方队重搜所有队友对；穷举模式比较指定池内全部交叉组合。报告列出好友／NPC 数、队友对覆盖、己方池大小、合法顺序数、实际测试数和理论交叉数。己方合法顺序或预计初筛超出 20,000 组、或队友对超出 10,000 组时明确拒绝，避免静默丢弃好友；可缩小己方范围。进行中的团战可预测原阵容；原生不提供队友选择框，须结束后才能搜索新队。
- 初测每组 128 次；按期望出招及区间筛选最多 8 个竞争候选，连同当前配置，用相同的新随机种子各独立复核 1024 次（顺序未知的好友为每种顺序各 1024 次）。每次完整模拟道中、中心与首领，继续按双方总出招的 `E[每次尝试] / P[通关]` 排序。初筛和复核都保留可展开的明细；有限候选与抽样误差仍可能影响排名，不保证全局最优。共享搜索复用私有原引擎实例，各次模拟重置原生存档、时钟和随机种子，不作用于真实游戏。

- 新模块沿用 `GameAdapter` 的唯一采样心跳；不增加轮询计时器，不修改游戏存档、时钟、随机数、孵化时间，也不跳过孵化动画。测试包含原生孵化属性验证、好友并集与出场顺序、成熟边界、手动预约、自动调度、PC 满和真实界面确认。
