# v2.1.1 代码审查

## 已修复

| 问题 | 影响与修复 | 回归证据 |
| --- | --- | --- |
| 多敌战中途仍获得 XP | 固定等级模型可能偷偷升级，影响先手和击杀次数；冻结所有经验奖励，添加等级不变断言 | 使用距离升级仅 1 XP 的候选连续对战 |
| 倒下只数终点状态 | 中心复活会掩盖之前损失；根据实际 HP 从正数到零的事件累计，次数可超过人数 | 同一只精灵在三场战斗中被击倒，中间治疗 |
| 非战斗全队倒下误判 | 正常中心治疗被当作失败；区分战斗失败与非战斗治疗 | 全队初始倒下，但下一节点为中心，允许复活 |
| 适用上限不一致 | 跨地区精灵升级扫描可能越界；每只候选保存其适用上限，扫描和运行统一检查 | 预算和现有超上限测试 |
| 路线输入/门槛未隔离 | 隐藏的无效指定目标会阻止路线运行；路线现在忽略无关目标，结果应用设置的门槛 | 无效旧目标不阻止路线，报告包含达标状态 |
| 普通参数错误销毁 Worker | 改正输入还必须重新下载游戏；区分初始化失败与可恢复运行错误 | 浏览器先提交未知物种，改正后直接成功计算 |
| 标签切换丢失表单 | 组件重挂载没恢复候选；保存本机分析条件并立即恢复已有快照 | 切页后样本数、候选与预估组数仍在 |
| 损坏的存储被覆盖 | 数组结构会吞掉新数据，非法 JSON 会丢失原文；保留不可识别根存储并可导出原文 | 非法 JSON、数组根数据、null 和 false 均保持原文 |

有界期望区间使用更保守的双侧置信参数。伤害区间、速度与状态逻辑仍使用已核验原引擎；没有降低断言或关闭摘要校验。

## 体验改进

- 计算组数和总样本在开始前可见，超预算直接提示。
- 一键恢复当前实际出战队伍，候选显示 HP、异常、闪光及强化信息。
- 记住分析条件；同物种的队伍结果带等级/强化信息，避免只看名字。
- 升级建议附额外经验成本，不只显示目标等级。

## 保留的边界

完整战斗期望依然是带置信范围的抽样估计，不是解析精确值；五六只队伍采用换位局部搜索。路线冻结时间与等级，不计实际升级/进化收益。真实玩家存档与登录战斗仍需游戏内验收。后续值得增加“进化前后对策收益/成本比较”和“失败轨迹摘要”，需要独立模型与样本支持。
